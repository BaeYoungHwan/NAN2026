# 팀원 롤 기술서 — 돌려돌려 그림자

## 1. 팀 구성

| 팀원 | 담당 역할 | 맡은 영역 |
|---|---|---|
| **배영환** | 게임 로직 · 아키텍처 · 인프라 | 전체 일정(WBS), 핵심 판정 설계, 절차적 스테이지 생성, 오디오, 빌드·배포 |
| **송원호** | 프론트엔드 UI · 콘텐츠 · QA | React UI, 캐릭터·그림자 비주얼, 스토리·컷신, 외부 AI 이미지 생성, QA |

**분업 기준** — "화면에 보이는 것"과 "화면 뒤에서 판정하는 것"으로 갈랐다. 서버가 없는 클라이언트 전용 프로젝트라 전통적인 프론트/백 구분이 성립하지 않아, 코드가 겹치지 않는 경계를 기준으로 나눴다.

## 2. 배영환 — 게임 로직 · 아키텍처 · 인프라

### 2.1 게임 핵심 로직

**절차적 스테이지 생성** (`src/procgen/`, ADR-003)
- 시드 기반 random-walk 통로 carve
- BFS 도달가능성 검증, 스폰-골 최소 거리 보장

**라운드 진행 시스템** (PR #4)
- 세이브 포인트 기반 1R → 2R → 3R 전환
- 3R 디메리트: 허용 각도 축소 + 이동키 반전

**다중 광원(가로등) 메커닉** (PR #7, ADR-004)
- 최근접 광원 기준 안전구역 판정
- **광원 전환 유예** — 전환 순간 요구 각도가 최대 180° 점프해 회피 불가능한 즉사 구간이 생겼다. 유예 시간으로 해소하고, 회전 속도와의 관계는 회귀 테스트로 고정했다

**라운드별 독립 스테이지** (PR #11)
- 라운드마다 파생 시드로 새 지형을 생성하도록 구조 변경
- 같은 PR에서 **이동 패턴 학습 AI(`src/ai/`)를 전량 제거**했다. 방문 빈도로 동선을 차단하는 기능이었으나, 라운드마다 지형이 바뀌는 구조에서는 학습 대상 자체가 사라졌다. 남겨두면 "동작하지만 의미 없는 코드"가 되므로 지웠다

**세이브 포인트 판정**
- 통과 시 파란 원 → 초록 원 시각 피드백 (PR #12)
- 이후 접촉 판정으로 전환 (PR #19) — 기존 판정은 방향 정보가 없는 스칼라 비교라, 반대편 갈래로 가도 통과 처리되는 정확성 버그가 있었다

**골 클리어 오판 수정 + 사운드 큐 정리** (PR #21)

### 2.2 오디오

**오디오 시스템 구축** (PR #19) — `src/audio/` 신설
- GainNode 3단 믹서, 큐별 쿨다운·피치 변조·BGM 크로스페이드
- 위험도 비례 경고음 — 2R부터 시각 가이드가 사라지는 공백을 청각으로 메운다
- 에셋 폴백: 파일이 없어도 게임이 멈추지 않는다
- **효과음 13종은 `scripts/generate-audio.mjs`로 직접 합성** (외부 의존성 0, 라이선스 팀 소유)

**BGM 루프 크래클 제거** (PR #24) — BGM만 `HTMLAudioElement` 스트리밍이라 루프 이음매마다 잡음이 났다. 효과음과 같은 `AudioBufferSourceNode` 재생으로 통일해 해소

**BGM 외부 음원 교체·가공** (PR #27) — 자체 합성 BGM이 지속음이라 음악으로 들리지 않았다
- OpenGameArt 음원으로 교체, 곡별 라이선스 검증 (CC0 3곡, CC-BY 2곡)
- 게임 내 크레딧 표기, 음량 정규화, 심리스 루프화
- MP3 Xing 헤더 누락으로 루프마다 46ms 무음이 끼던 문제 규명·수정

### 2.3 아키텍처 · 인프라

**문서 체계 수립** — ADR/PRD/ARD 체계와 Claude Code 하네스(`CLAUDE.md`, `docs/ref/`) 구성. 설계 결정은 코드보다 ADR을 먼저 쓰는 절차로 고정

**심사 첫인상 개선 + 밸런스 파라미터 집약** (PR #26)
- 타이틀 화면 신설, 페이지 셸·favicon, HUD 정리
- 라운드 페이드, 엔딩 결과 요약, DPR·뷰포트 대응
- 흩어져 있던 밸런스 상수 13개를 `core/tuning.ts`로 집약, `?tune=1` 실시간 튜닝 패널 추가

**배포 파이프라인** (PR #10, #25) — GitHub Actions 기반 Pages 자동 배포. 배포 직전 테스트 게이트를 걸어 `main`에 직접 들어간 변경도 검증을 통과해야 나가게 했다

**제출물 문서** — 게임소개·AI 활용 기술문서·팀원 롤 기술서 초안, README 제출물 현황표 (PR #13~#16), 게임 제목 확정 반영 (PR #18)

**코드 리뷰** — 송원호가 올린 PR을 검토하고 병합

- "그림자씨" 디자인 시트에서 개별 스프라이트 추출 (`scripts/crop-regions.mjs`, 코너 플러드필 배경 제거)
- **2프레임 걷기 사이클** — 상체 고정 + 다리만 좌우 반전. 다리 하나만 회전시키는 방식(한쪽 다리로만 뛰는 것처럼 보임)과 몸 전체를 반전하는 방식(얼굴 방향까지 뒤집힘)을 차례로 폐기한 끝에 정착했고, 그 경위를 `characterSprites.ts` 주석에 남겼다
- 위험도(`alignmentMargin`) 기반 몸 포즈·그림자 표정 전환, 정렬 이탈 시 4단계 죽음 애니메이션

### 3.3 배경 · 텍스처

**비주얼 정비 + 2R/3R 배경** (PR #17) — 캐릭터·벽·광원·세이브포인트 표현 정비

**바닥/벽 실사 타일 텍스처** (PR #20)
- 프롬프트 가이드로 생성한 seamless 타일 적용
- 바닥과 벽의 무늬 반복 주기가 달라(픽셀 밝기 프로파일로 실측) 각각 다른 스케일을 산출
- 로드 실패 시 기존 절차적 렌더링으로 자동 폴백

**웅덩이 반사 제거 + 저승사자 대화창 초상** (PR #23) — 가로등 발치 반사가 가로등 자체와 혼동된다는 플레이 피드백을 반영해 제거, 대사창에 초상 추가

**타일 프롬프트 가이드 작성** (`tile-art-prompt-guide.md`) — 프롬프트를 즉흥적으로 짜면 재생성 때마다 결과가 흔들리므로, 스타일 앵커와 기술 제약을 재사용 가능한 템플릿으로 고정했다. 배경 가이드(`background-art-prompt-guide.md`)는 배영환이 만든 문서를 2R/3R 배경을 추가하며 함께 갱신했다

### 3.4 문서 · QA

**AI 활용 기술문서 콘텐츠/QA 파트 집필** (PR #22)

**QA** — 오프닝부터 엔딩까지 전체 플레이스루 검증, 체크포인트/리스폰 정확성 확인. 에셋 출처·라이선스 문서(`public/assets/ASSET_SOURCES.md`)를 처음 만들고 이미지 에셋 항목을 관리했다 (오디오·BGM 항목은 배영환이 추가)

**코드 리뷰** — 배영환이 올린 PR을 AI 코드 리뷰 도구로 검토해 지적 사항을 전달했다. 게임 로직·오디오처럼 직접 구현하지 않은 영역까지 리뷰가 닿을 수 있었던 것은 이 방식 덕분이다

## 4. 협업 · 분업 방식

### 4.1 브랜치 전략

`main`(배포) ← `develop`(통합) ← `feature/*` 및 개인 브랜치. 각자 작업을 브랜치로 분리해 PR로 병합하며, `main`은 배포 전 테스트 게이트를 통과해야 한다.

### 4.2 역할 분리와 그 한계

배영환이 판정·생성·오디오·인프라를, 송원호가 화면에 보이는 모든 것과 콘텐츠·QA를 담당했다. 다만 **역할은 갈렸어도 파일은 갈리지 않았다.**

- 렌더·게임 루프·판정이 `GameCanvas.tsx`(약 1,320줄)와 `drawStage.ts`(약 790줄) 두 파일에 몰려 있다
- 그래서 두 사람의 커밋이 같은 파일에 겹쳤다 (`GameCanvas.tsx` 기준 29:19)
- 오디오 시스템(PR #19)은 세이브 포인트 판정과 코드가 맞물려 PR 분리가 불가능했다
- 이 구조 문제를 기술 부채(`docs/exec-plans/tech-debt-tracker.md` TD-001·TD-003)로 명시하고, 마감 전 회귀 위험이 커서 손대지 않기로 결정한 뒤 본선 과제로 이월했다

### 4.3 상호 리뷰 — 모든 PR이 상대의 검토를 거쳐 병합됐다

- **송원호 → 배영환**: 송원호가 올린 PR은 배영환이 리뷰한 뒤 병합
- **배영환 → 송원호**: 배영환이 올린 PR은 송원호가 **AI 코드 리뷰 도구를 써서** 검토하고, 배영환이 병합 시점에 지적 하나하나를 다시 판단했다

AI가 지적을 만들고 **채택 여부는 사람이 정하는** 구조다. 2인 팀에서 서로의 코드를 놓치지 않으려면 리뷰의 밀도를 사람 수로만 감당할 수 없었다.

### 4.4 리뷰는 형식적 승인이 아니었다

반복 라운드를 도는 리뷰를 했고, 지적과 수정 내역은 PR별 "리뷰 반영" 커밋으로 이력에 남아 있다.

| PR | 라운드 | 잡아낸 것 |
|---|---|---|
| #9 | 반영 커밋 5개 | 사망·대사창 표시 중 방향/걷기 포즈가 실시간 입력에 새던 문제, 원본 디자인 시트가 배포에 포함되던 문제, 그림자 표정이 연결되지 않은 채 남아 있던 문제 |
| #23 | 4차까지 | 제출물 문서 유실 복구, 대사창 폭 안전장치, 에셋 폴백, 반응형 초상 폭 |
| #26 | 3차 / 지적 14건 | 튜닝 패널이 3R에서 1R로 튕기던 문제, DOM을 클래스명으로 거슬러 올라가던 결합, 위험도 상수가 네 곳에 흩어져 조용히 어긋날 수 있던 구조 |
| #27 | 2차 | BGM 루프 무음, 크레딧 표기 견고화, 크레딧 스크롤바 클릭이 게임을 시작시키던 회귀 |

### 4.5 문서 동기화와 범위 관리

**문서 동기화** — 아키텍처가 바뀌면 관련 문서를 같은 PR이나 후속 PR에서 함께 갱신한다. 설계 결정은 ADR에, 진행 상태는 `docs/exec-plans/`에, 제출물 원고는 `docs/submission/`에 두어 작업용 문서와 제출용 최종본을 분리했다.

**범위 관리** — `CLAUDE.md`에 MVP 범위 제한(회원가입·랭킹·마우스 조작 등)을 명시해, 마감이 정해진 사전과제에서 범위가 번지지 않도록 가드레일을 걸었다. 의의가 사라진 기능(이동 패턴 학습 AI)은 아깝다고 남기지 않고 제거했다.
