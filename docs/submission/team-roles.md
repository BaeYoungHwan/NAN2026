> 사전과제 제출물 5종 중 5번 항목. 대회 안내(`NAN2026.md`) 기준 필수 3항목을 다룬다:

## 팀 구성

2인 팀 — 배영환(게임 로직·아키텍처·인프라), 송원호(프론트엔드·UI/콘텐츠/QA)

작업은 **"화면에 보이는 것"과 "화면 뒤에서 판정하는 것"** 으로 갈랐다. 서버가 없는 클라이언트 전용 프로젝트라 전통적인 프론트/백 구분이 성립하지 않기 때문에, 코드가 겹치지 않는 경계를 기준으로 나눴다.

## 배영환 — 게임 로직·아키텍처·인프라

**담당 역할**: 전체 일정(WBS) 관리, 게임 핵심 로직·판정 설계, 절차적 스테이지 생성, 오디오, 빌드·배포 파이프라인

**실제 구현 영역** (PR 기준):

- **아키텍처·문서 체계 수립** — ADR/PRD/ARD 체계와 Claude Code 하네스(`CLAUDE.md`, `docs/ref/`) 구성. 설계 결정은 코드보다 ADR을 먼저 쓰는 절차로 고정
- **절차적 스테이지 생성**(`src/procgen/`) — 시드 기반 random-walk 통로 carve, BFS 도달가능성 검증, 스폰-골 최소 거리 보장 (ADR-003)
- **라운드 진행 시스템** — 세이브 포인트 기반 1R→2R→3R 전환 + 3R 디메리트(허용 각도 축소, 이동키 반전) (PR #4)
- **다중 광원(가로등) 메커닉** — 최근접 광원 기준 안전구역 판정, **광원 전환 유예**(전환 순간 요구 각도가 최대 180° 점프해 회피 불가능한 즉사 구간이 생기는 문제를 유예 시간으로 해소. 회전 속도와의 관계는 회귀 테스트로 고정) (PR #7, ADR-004)
- **라운드별 독립 스테이지 전환**(PR #11) — 라운드마다 파생 시드로 새 지형을 생성하도록 구조를 바꿨다. **같은 PR에서 이동 패턴 학습 AI(`src/ai/`)를 전량 제거**했다 — 방문 빈도로 동선을 차단하는 기능이었으나, 라운드마다 지형이 바뀌는 구조에서는 학습 대상 자체가 사라져 존재 의의가 없어졌다. 남겨두면 "동작하지만 의미 없는 코드"가 되므로 지웠다
- **세이브 포인트 판정** — 통과 시 파란 원→초록 원 시각 피드백(PR #12), 이후 **접촉 판정으로 전환**(PR #19). 기존 판정은 방향 정보가 없는 스칼라 비교라 반대편 갈래로 가도 통과 처리되던 정확성 버그가 있었다
- **오디오 시스템 구축**(PR #19) — `src/audio/` 신설. GainNode 3단 믹서, 큐별 쿨다운·피치 변조·BGM 크로스페이드, 위험도 비례 경고음(2R부터 시각 가이드가 사라지는 공백을 청각으로 메움), 에셋 폴백. **효과음 13종은 `scripts/generate-audio.mjs`로 직접 합성**(외부 의존성 0, 라이선스 팀 소유)
- **BGM 외부 음원 교체·가공**(PR #24, #27) — 자체 합성 BGM이 지속음이라 음악으로 들리지 않아 OpenGameArt 음원으로 교체. 곡별 라이선스 검증(CC0 3곡, CC-BY 2곡), 음량 정규화, 심리스 루프화, MP3 Xing 헤더 누락으로 루프마다 46ms 무음이 끼던 문제 규명·수정
- **골 클리어 오판 수정 + 사운드 큐 정리**(PR #21)
- **심사 첫인상 개선 + 밸런스 파라미터 집약**(PR #26) — 타이틀 화면 신설, 페이지 셸·favicon, HUD 정리, 라운드 페이드/엔딩 결과 요약, DPR·뷰포트 대응. 흩어져 있던 밸런스 상수 13개를 `core/tuning.ts`로 모으고 `?tune=1` 실시간 튜닝 패널 추가
- **배포 파이프라인**(PR #10, #25) — GitHub Actions 기반 Pages 자동 배포. 배포 직전 테스트 게이트를 걸어 `main`에 직접 들어간 변경도 검증을 통과해야 나가게 했다
- **제출물 문서** — 게임소개·AI 활용 기술문서·팀원 롤 기술서 초안, README 제출물 현황표 (PR #13~#16), 게임 제목 확정 반영 (PR #18)

## 협업·분업 방식

- **브랜치 전략**: `main`(배포) ← `develop`(통합) ← `feature/*` 및 개인 브랜치 — 각자 작업을 브랜치로 분리해 PR로 병합한다. `main`은 배포 전 테스트 게이트를 통과해야 한다
- **역할 분리**: 배영환이 판정·생성·오디오·인프라를, 송원호가 화면에 보이는 모든 것과 콘텐츠·QA를 담당했다. 겹치는 파일이 거의 없어 두 사람이 동시에 작업해도 충돌이 드물었다
- **코드 리뷰가 실제로 버그를 잡았다** — 형식적 승인이 아니라 반복 라운드를 도는 리뷰를 했다.
  - PR #9: 5라운드에 걸쳐 상태 관리 버그(사망·대사창 표시 중 입력이 새는 문제 등)를 발견·수정
  - PR #23: 4차 리뷰까지 진행 — 제출물 문서 유실 복구, 대사창 폭 안전장치, 에셋 폴백, 반응형 초상 폭
  - PR #26: 리뷰 지적 9건을 두 차례에 걸쳐 수정 — 튜닝 패널이 3R에서 1R로 튕기던 문제, DOM을 클래스명으로 거슬러 올라가던 결합, 위험도 상수가 네 곳에 흩어져 조용히 어긋날 수 있던 구조 등
  - PR #27: 2차 리뷰 — BGM 루프 무음, 크레딧 표기 견고화, 크레딧 스크롤바 클릭이 게임을 시작시키던 회귀
- **문서 동기화**: 아키텍처가 바뀌면 관련 문서를 같은 PR이나 후속 PR에서 함께 갱신한다. 설계 결정은 ADR에, 진행 상태는 `docs/exec-plans/`에, 제출물 원고는 `docs/submission/`에 두어 작업용 문서와 제출용 최종본을 분리했다
- **범위 관리**: `CLAUDE.md`에 MVP 범위 제한(회원가입·랭킹·마우스 조작 등)을 명시해, 마감이 정해진 사전과제에서 범위가 번지지 않도록 가드레일을 걸었다. 의의가 사라진 기능(이동 패턴 학습 AI)은 아깝다고 남기지 않고 제거했다
