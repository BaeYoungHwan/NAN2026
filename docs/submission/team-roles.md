## 배영환 — 백엔드/아키텍처/WBS 총괄

**담당 역할**: 전체 일정(WBS) 관리, 게임 핵심 로직·아키텍처 설계, 절차적 생성 알고리즘, 이동 패턴 학습 AI

**실제 구현 영역** (PR 기준):
- 프로젝트 아키텍처 초안 — ADR, PRD, ARD 문서 체계 수립
- 스테이지 절차적 생성(`src/procgen/stageGenerator.ts`) — 시드 기반 random-walk 통로 생성, 도달가능성(BFS) 검증
- 라운드 진행 시스템 — 세이브 포인트 기반 1R→2R→3R 전환 + 3R 디메리트(허용 각도 축소, 이동키 반전) (PR #4)
- 이동 패턴 학습 AI (`src/ai/pathBlocker.ts`) — 방문 빈도 기반으로 자주 다니는 경로를 재시작마다 최대 4셀까지 차단, 스테이지 도달 불가 상태는 만들지 않도록 사전 검증 (PR #5, #6)
- 다중 광원(가로등) 메커닉 — 최근접 광원 기반 안전구역 판정, 광원 전환 유예 시간 (ADR-004, PR #7)
- 스테이지 배경 아트 방향 — 외부 AI 이미지 생성 프롬프트 가이드 작성 (PR #8)
- GitHub Pages 배포 — `develop → main` 병합, Actions 기반 배포 파이프라인 구성 (PR #10)

## 협업·분업 방식

- **브랜치 전략**: `main`(배포) ← `develop`(통합) ← `feature/*` 및 개인 브랜치(`wonho`) — 각자 작업을 브랜치로 분리 후 PR로 병합
- **역할 분리**: 배영환이 게임 로직·판정·AI·인프라를, 송원호가 화면에 보이는 모든 것(UI, 캐릭터/그림자 비주얼, 스토리 콘텐츠)과 QA를 담당 — 겹치는 코드가 거의 없어 병렬 진행이 가능했음
- **코드 리뷰**: PR마다 서로 리뷰 — 예) PR #9는 배영환의 리뷰를 거쳐 5라운드에 걸쳐 상태 관리 버그(사망/대사창 중 입력이 새는 문제 등)를 찾아 수정
- **문서 동기화**: 아키텍처 변경(예: 다중 광원 ADR-004) 발생 시 관련 문서(배경 아트 가이드 등)를 같은 PR 또는 후속 PR에서 함께 갱신
