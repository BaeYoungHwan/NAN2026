## 1. 개요

**돌려돌려 그림자** — NHN 주최 NAN2026 AI 게임 개발 해커톤(https://nan2026.nhn.com/) 사전과제 제출용 웹 게임. 플레이어는 캐릭터(WASD 이동)와 그림자(`,`/`.` 회전)를 동시에 조종하는 이중 조작 키보드 전용 액션 퍼즐 싱글 플레이 게임이다. 광원(태양)은 스테이지마다 고정된 위치를 가지며, 캐릭터 뒤(광원 반대 방향) ± 허용 각도가 "안전 구역"으로 매 프레임 재계산된다. 그림자는 이 안전 구역과 무관하게 플레이어가 직접 설정한 각도를 그대로 유지하므로, 캐릭터를 움직이면 안전 구역이 이동해 그림자와 어긋난다 — 그림자 각도가 안전 구역을 벗어나는 순간 즉사·스테이지 리셋된다.

## 2. 문제 정의

NAN2026은 서류·사전과제 심사를 통과한 10팀만 본행사(2026-09-04~06, 48시간 개발)에 진출할 수 있다. 사전과제는 자유 주제 웹 게임을 완성해 제출해야 하며, 마감(2026-08-10)까지 약 18일밖에 남지 않은 상태에서 컨셉 확정부터 빌드·제출물 5종까지 완료해야 한다. 캐릭터 이동(WASD)과 그림자 회전(`,`/`.`)을 동시에 조작해야 하고, 캐릭터를 움직이면 그림자가 맞춰야 할 각도 자체가 바뀐다는 점에서 "이중 조작형 퍼즐"로 차별화해, 짧은 개발 기간에도 완성도 있는 단일 메커니즘 게임을 만드는 것이 목표다.

## 4. 성공 지표 (KPI)

- 사전과제 심사 통과 — 전체 지원팀 중 상위 10팀 선발 (2026-08-22 발표)
- 본행사(2026-09-04~06) 수상권(대상/최우수상/우수상) 진입
- 스테이지 평균 클리어율 40~60% 유지 (적절한 난이도)
- 유저 평균 플레이 타임 10분 이상
- 재시도(Retry) 횟수 스테이지당 평균 3회 이상 (도전 욕구 자극)

## 5. 기술 스택

**TypeScript + React + HTML5 Canvas** (확정). UI 레이어는 React, 게임 렌더링·그림자 계산·각도 판정은 Canvas를 직접 제어한다. 절차적 스테이지 생성은 클라이언트(JS) 측에서 수행해 서버 비용을 없앤다.

## 6. 배포 환경

GitHub Pages (웹 빌드 필수, 링크 클릭만으로 브라우저에서 바로 플레이 가능해야 함). 저장소: https://github.com/BaeYoungHwan/NAN2026

## 7. MVP 핵심 기능

> 이번 버전에서 반드시 구현할 기능

- [x] WASD / 방향키 기반의 캐릭터 이동 시스템
- [x] `,`/`.` 기반 그림자 직접 회전 (광원 위치와 무관하게 유지, 자동 복귀 없음)
- [x] 광원(태양) 고정 위치 + 캐릭터 위치로 매 프레임 재계산되는 안전 구역(캐릭터 뒤 ± 허용 각도) 계산 로직
- [x] 그림자 각도 이탈 판정 (즉사 및 스테이지 리셋 — 그림자 각도가 안전 구역을 벗어나는 순간 발동)
- [x] 스테이지 지형(벽/통로)·광원·스폰·골 위치 절차적 생성 — 시드 기반 random-walk carve, 벽-캐릭터 충돌판정, 골 도달 시 클리어. 시각 에셋은 미정이라 기본 도형으로 렌더링(추후 아트 교체 가능하도록 렌더링 로직 분리)
- [x] 라운드 진행 시스템 (1R: 가이드라인 표시 → 2R: 가이드라인 제거 → 3R: 디메리트 적용) — `src/core/round.ts` 전체(전환·가이드라인·디메리트) 구현 완료. 각 라운드는 독립적으로 생성된 별도 스테이지이며(결정론적 시드 파생, `seedForRound`), 스테이지 내부에는 진척도 기반 세이브 포인트가 있어 사망 시 마지막으로 넘은 지점(없으면 스폰)으로 리스폰한다
- [x] 저승사자 NPC 대사 (텍스트 대사 박스 — 튜토리얼 안내 겸 병맛 코미디) — `DialogueBox.tsx`+`content/reaperLines.ts` 구현 완료, 스크립트는 초안이며 추후 교체 예정
- [x] 오프닝/엔딩 컷신 (텍스트+정적 이미지 수준) — `CutsceneSlide.tsx`+`content/cutsceneSlides.ts` 구현 완료(텍스트 슬라이드, 정적 이미지는 미포함)
- [x] 실패 시 즉시 재시작(리트라이) 흐름 (캔버스 HUD 수준)
- [x] 최소 UI (조작법 안내, 재시작 버튼, 클리어 표시, 현재 라운드 표시 — 정식 React UI) — `HUD.tsx`/`RestartButton.tsx` 구현 완료

## 7-1. 라운드 구조 (페이즈 진행)

각 라운드(1R/2R/3R)는 독립적으로 생성된 별도 스테이지이며(결정론적 시드 파생), 라운드가 올라갈수록 난이도가 올라간다. 한 라운드의 골에 도달하면 다음 라운드용 새 스테이지가 그 자리에서 생성되어 전환된다. 스테이지 내부에는 진척도 기반 세이브 포인트가 있어, 사망 시 마지막으로 넘은 세이브 포인트(없으면 스폰)로 리스폰한다.

| 라운드 | 핵심 변화 |
|--------|-----------|
| 1R | 안전 구역(부채꼴) 가이드라인이 화면에 표시됨 — 그림자가 있어야 할 각도 범위를 시각적으로 보여줌 |
| 2R | 가이드라인 제거 — 플레이어가 안전 구역 위치를 스스로 기억/추측해야 함 |
| 3R | 디메리트 적용 — 허용 각도 절반 축소 + WASD 이동키 상하좌우 반전 (구현 완료, 수치는 임시값·§12 참고) |
| 4R | 개념은 존재하나 이번 사전과제 데모 범위 밖 — 본선 또는 이후 개발에서 제작 |

- 이번 사전과제 데모는 **1R~3R까지만 구현**한다. 4R은 명시적 요청 전까지 구현하지 않는다.
- 3R 디메리트(허용 각도 절반 축소 + 조작키 반전)는 구현 완료. 배율·반전 범위 등 구체 수치는 임시값이며 P1 플레이테스트로 조정한다 — §12 참고.

## 7-2. 스토리 및 연출

**설정**: 저승사자가 실수로 주인공을 저승으로 데려간다 (동명이인 착오 — 원래 데려가야 할 사람은 따로 있었음). 주인공은 아직 죽을 때가 아니라서 이승으로 돌아가야 하는데, 저승-이승 경계를 넘는 동안 그림자가 불안정해져 몸(캐릭터)과 그림자를 따로 붙잡고 있어야 한다. 그림자가 몸 뒤의 안전한 위치(경계)를 벗어나면 영혼이 저승에 붙잡혀 즉사 — 이 설정이 "캐릭터·그림자 이중 조작 + 각도 이탈 시 즉사" 메커닉의 서사적 근거가 된다.

**저승사자 NPC**: 실수를 저지르고도 도움은 안 되면서 옆에서 "죄송합니다 제가 실수했어요", "빨리 넘어가세요 제 실적에 들어가면 안 돼요" 같은 대사로 재촉하는 병맛 코미디 캐릭터. 조작법·지형 등 튜토리얼 설명을 대사로 전달하는 역할을 겸한다.

**구현 범위 (MVP)**:
- 저승사자 대사: 텍스트 대사 박스 (전용 애니메이션·음성 없음)
- 오프닝 컷신: 저승사자의 실수를 알리는 도입부 — 텍스트+정적 이미지 수준
- 엔딩 컷신: 경계 통과 성공 후 마무리 — 텍스트+정적 이미지 수준
- 컷신은 별도 애니메이션·동영상 제작 없이 정적 이미지·텍스트 슬라이드 전환으로 구현 (제작 리소스 최소화, 18일 일정에서 핵심 메커닉 작업 시간 확보 우선)

## 8. MVP 제외 사항 ⚠️

> Claude는 아래 항목을 임의로 구현하지 않습니다.

- 사용자 회원가입 및 로그인
- 랭킹 시스템 및 글로벌 리더보드
- 마우스 컨트롤 지원 (키보드 단독 조작 원칙)
- 아이템, 스킬, 광원 직접 조작 기믹
- 복잡한 그래픽 셰이더 및 3D 그래픽 효과
- PC 실행파일(.exe) 빌드 — 대회 규정상 제출 불가
- 유료 라이선스가 필요한 에셋 사용
- 4R 이상 라운드 — 이번 사전과제 데모는 1R~3R까지만 구현, 4R은 본선/이후 개발로 보류

## 9. 제약사항

- 웹 브라우저에서 키보드 단독 조작으로만 완벽 플레이 가능해야 함
- 외부 서버 비용을 최소화하기 위해 클라이언트 측(JS)에서 절차적 스테이지 생성 수행
- PC 실행파일(.exe) 제출 불가 — 웹 또는 모바일 앱만 허용
- 별도 유료 라이선스 없이 심사자가 바로 실행 가능해야 함
- 외부 에셋(이미지·사운드 등) 사용 시 출처·라이선스를 AI 활용 기술문서에 반드시 명시
- AI 도구 사용 내역(도구명, 주요 프롬프트)을 반드시 문서화
- 플레이 영상은 AI 합성·타인 영상 도용 금지, 실제 플레이 화면만 사용
- 저장소는 공개(public) 권장, 비공개 시 심사 계정(dl_gameai_reviewer@nhn.com) 초대 필요
