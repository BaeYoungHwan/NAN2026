## 배영환 — 백엔드/아키텍처/WBS 총괄

### 담당 역할
- 전체 WBS·일정 수립 및 진척도 관리
- 핵심 아키텍처 설계 및 기술 리스크 담당 (그림자 판정 로직, 절차적 생성, 물리/충돌)
- AI(Claude Code) 활용 워크플로우 설계 — 하네스 구성, Plan 모드 기반 작업 절차

### 실제로 맡아 구현한 영역 (커밋 로그 기준)

| 영역 | 내용 |
|---|---|
| 레포 골격·배포 | 프로젝트 초기 설정(`feature/repo-scaffold`), GitHub Pages 배포 파이프라인 구성, 3단계 브랜치 전략(main/develop/feature) 수립 |
| 핵심 판정 로직 | `ShadowCaster`·`ContainmentJudge` 구현 (그림자 각도 vs 안전구역 판정, ADR-001/002) — 최초 단일 판정 모델에서 캐릭터·그림자 이중 조작(각도 허용치) 모델로 재설계 |
| 절차적 스테이지 생성 | 타일 그리드 + random-walk carve + 충돌판정자 주입 방식 설계·구현(ADR-003), 벽-캐릭터 축 분리 이동 처리 |
| 라운드 시스템 | 1R~3R 세이브 포인트 기반 진행, 3R 디메리트(허용각도 축소+조작키 반전), 이후 라운드마다 독립 스테이지(새 파생 시드)로 재설계 |
| 다중 광원 메커닉 | 최근접 광원 기준 안전구역 판정(ADR-004), 광원 전환 순간 유예(`LIGHT_SWITCH_GRACE_SECONDS`) 처리 — 같은 커밋에서 구현했지만 ADR 본문엔 반영 안 됨(별도 정리 필요) |
| 버그 발견·수정 | 그림자 렌더링 퇴화(수평 각도 시 그림자 소실), 진척도 판정이 벽을 무시하던 정확성 버그(BFS 거리 필드로 교체), 체크포인트 좌표 겹침·라운드 시드 충돌 — 모두 시드 sweep/브라우저 실측으로 재현 후 수정, 회귀 테스트 추가 |
| 이동 패턴 학습 AI | 초기 구현(빈도 기반 동선 차단) 후, 게임 목표와의 정합성 재검토를 거쳐 완전 제거 결정 |
| 세이브 포인트 UX | 통과 시 시각 피드백(색상 변화) 추가 |
| AI 활용 워크플로우 | Claude Code 하네스 구성(`CLAUDE.md`, 모델 라우팅, MVP 범위 가드레일), AI활용기술문서 초안 작성 |

### 협업·분업 방식
- API/데이터 계약(Stage, TileGrid 등 타입 정의)을 초반에 합의하고 병렬 진행 — 절차적 생성은 시각 에셋과 무관하게 순수 데이터(그리드) 레벨로 설계해, 송원호님의 아트 작업과 독립적으로 진행 가능하도록 분리
- 코드 리뷰 1인 이상 후 `develop` 머지 원칙 적용, PR 단위로 작업 분리
- 담당 영역 밖(UI/콘텐츠) 작업은 송원호님 브랜치(`wonho`)에서 별도 진행 후 병합
