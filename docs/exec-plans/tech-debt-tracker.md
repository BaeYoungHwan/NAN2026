# 기술 부채 추적

`doc-gardener` 에이전트와 수동 검토로 발견된 기술 부채를 기록합니다.

---

## 활성 부채

| ID | 유형 | 설명 | 발견일 | 우선순위 |
|----|------|------|--------|----------|
| TD-001 | `test-gap` | **게임 루프 상태 전이에 통합 테스트가 없다.** 사망 판정→리스폰, 골 접촉→라운드 전환, 광원 전환 유예, 체크포인트 래치 같은 핵심 규칙이 전부 `GameCanvas.tsx`의 rAF 클로저(`draw`) 안에 있어 밖에서 호출할 방법이 없다. 현재 테스트는 거기서 뽑아낸 순수 함수(`selectBodyPose`, `deathFrameInfo`, `roundFadeAlpha`, `canvasDisplayScale` 등)만 덮는다. 해소 방향: `stepGame(state, input, dt) → state` 형태의 순수 상태 머신 추출 | 2026-08-05 | 중 (본선 48시간 대비) |
| TD-002 | `perf` | **`drawStage.ts`의 오프스크린 레이어가 DPR을 반영하지 않는다.** 바닥·벽 레이어를 논리 해상도(맵 크기)로 만들어 카메라 줌(2.2×)만큼 업스케일한다 — DPR 대응(2026-08-05)을 넣었지만 이 레이어들만 선명도 이득을 못 본다. 회귀는 아님(원래 그랬음). 해소하려면 3개 빌더(`buildFloorTileLayer`/`buildFloorGrain`/`buildWallLayer`)와 캐시 키에 배율을 함께 넣어야 한다 | 2026-08-05 | 낮음 |
| TD-003 | `layer-violation` | **렌더·게임 루프·판정이 두 거대 파일에 몰려 있다.** `GameCanvas.tsx` ≈1320줄, `drawStage.ts` ≈790줄(2026-08-07 실측 — 심사 첫인상 개선으로 `GameCanvas.tsx`가 더 늘었다). TD-001과 같은 뿌리다 — 루프/판정/렌더러를 분리하면 둘 다 풀린다. 마감(2026-08-10) 전에는 회귀 리스크가 커서 손대지 않기로 결정 | 2026-08-05 | 중 (본선 48시간 대비) |
| TD-004 | `doc-drift` | **`docs/QUALITY_SCORE.md`가 템플릿 상태 그대로다.** 채우거나 제거해야 한다 | 2026-08-05 | 낮음 |
| TD-005 | `dead-code` | **개발 전용 튜닝 패널 청크가 배포본에 남는다.** `React.lazy`로 메인 번들에서는 분리했고(`dist/assets/TuningPanel-*.js` 3.5KB) 프로덕션에서는 `isTuningEnabled()`가 false라 **내려받지 않는다** — 실행 위험은 없다. 다만 파일 자체는 `dist/`에 배포된다. 완전히 없애려면 빌드 타임 조건부 alias(프로덕션에서 빈 모듈로 치환)가 필요한데 설정 복잡도 대비 이득이 작아 보류 | 2026-08-06 | 낮음 |
