# ADR-002: 그림자 이중 조작 — 각도 허용치 기반 판정으로 전환

> 상태: Accepted
> 날짜: 2026-07-23
> 결정자: 배영환, 송원호
> 이전 결정: [ADR-001](ADR-001-shadow-boundary-judgment.md) (Superseded)

## 컨텍스트

ADR-001은 "그림자가 캐릭터 위치로부터 파생되어 레벨에 고정된 안전 경계(폴리곤) 안에 있어야 한다"는 전제로 기하학적 포함 판정을 설계했다. 그러나 실제로 render-prototype을 플레이해본 결과, 사용자가 의도한 게임 기획은 다음과 같음이 확인됐다:

- 플레이어는 **두 객체를 동시에 조종**한다 — 캐릭터(WASD)와 그림자(`,` 시계방향 / `.` 반시계방향 회전)
- 그림자의 실제 각도는 광원 위치와 무관하게 **플레이어가 직접 설정한 값을 그대로 유지**한다 (자동 복귀·자동 추종 없음)
- "안전 구역"은 레벨에 고정된 폴리곤이 아니라 **캐릭터에 부착되어 캐릭터 뒤(광원 반대 방향)로 매 프레임 재계산**된다 — 캐릭터가 움직이면 광원과의 상대 위치가 바뀌므로 "안전한 각도" 자체가 계속 이동한다

즉 캐릭터 이동(WASD)은 "필요한 각도"를 바꾸고, 그림자 회전(`,`/`.`)은 "실제 각도"를 바꾼다. 둘을 계속 맞춰야 하는 것이 퍼즐의 핵심이며, ADR-001의 "레벨 고정 폴리곤 포함 판정"은 이 구조와 맞지 않는다.

## 결정

안전 구역을 **광원-캐릭터 방향(자연 각도) ± 허용 각도**의 각도 범위로 정의하고, 그림자의 실제 각도가 이 범위 안에 있는지를 **각도 차이 비교**로 판정한다.

**선택: 각도 허용치(angle tolerance) 비교 방식**

## 고려한 대안

| 옵션 | 장점 | 단점 | 탈락 이유 |
|------|------|------|-----------|
| 각도 허용치 비교 (채택) | 계산이 매우 단순(뺄셈+wrap), 캐릭터-부착 구역을 자연스럽게 표현, ADR-001의 "기하학적·readback 없음" 장점 그대로 유지 | 오목한 커스텀 형태의 안전 구역은 표현 불가(부채꼴만) | - |
| ADR-001의 폴리곤 포함 판정 유지 + 캐릭터 위치로 폴리곤을 매 프레임 재생성 | 기존 코드 재사용 가능 | 부채꼴(각도 범위)을 다각형으로 근사해야 해서 오히려 더 복잡하고 부정확함. 그림자가 "각도"라는 1차원 상태라는 본질을 반영 못 함 | 문제를 더 복잡하게 만듦 |

## 결과

**긍정적 결과:**
- `ShadowCaster`(각도 계산)와 `ContainmentJudge`(각도 비교)가 모두 순수 함수로, 단위 테스트로 정확성 고정 가능 (16개 테스트 통과)
- `Stage`에서 `boundaryPolygon` 필드 제거 — 더 이상 필요하지 않은 데이터를 계약에서 삭제해 단순화
- 캐릭터 이동과 그림자 회전이라는 두 입력 축이 코드 구조상으로도 명확히 분리됨 (`physics/character.ts` vs `shadow/shadowCaster.ts`)

**부정적 결과 / 트레이드오프:**
- 안전 구역이 항상 "캐릭터 중심 부채꼴"이라는 단일 형태로 고정됨 — 다른 형태(예: 특정 지점에 고정된 목표 실루엣)가 필요해지면 이 모델을 다시 확장해야 함
- ADR-001에서 만든 `isPointInConvexPolygon`/폴리곤 포함 판정 코드는 이번 변경으로 폐기됨 (레벨 장애물·벽 충돌 등 다른 용도로 재사용 여지는 있으나 현재는 미사용)

**위험 요소:**
- 회전 속도·허용 각도 상수(`ROTATION_SPEED`, `SAFE_ANGLE_TOLERANCE`)가 아직 튜닝되지 않은 임시값 — 완화 방법: P1 플레이테스트로 실제 조작감 확인 후 조정

## 구현 시 주의사항

- 그림자 각도는 리셋 시 `naturalAngle(light, spawn)`으로 초기화한다 — 스폰 직후 항상 안전한 상태로 시작해야 함
- 각도 차이 계산은 반드시 `(-π, π]`로 정규화해서 비교한다 (359도와 1도 차이 = 2도, 358도 아님) — 이 처리를 빠뜨리면 원 경계 근처에서 억울한 죽음이 발생함
- `,`(시계방향)/`.`(반시계방향)의 화면상 실제 회전 방향은 캔버스 좌표계(y축 아래 방향)에서 시각적으로 검증 완료 (브라우저 실측)

## 재검토 조건

- 안전 구역이 부채꼴이 아닌 다른 형태(예: 특정 실루엣과 정확히 일치해야 하는 형태)로 바뀌어야 하는 경우
- 장애물이 그림자 회전 가능 범위를 물리적으로 막아야 하는 기믹이 추가되는 경우
