# ADR-001: 그림자 경계 판정 방식 — 기하학적/벡터 방식 채택

> 상태: Accepted
> 날짜: 2026-07-23
> 결정자: 배영환, 송원호

## 컨텍스트

Shadow-Step의 핵심 생존 조건은 "광원 고정 위치 + 캐릭터 위치로 계산되는 그림자가, 스테이지에 정의된 안전 경계(바운더리) 안에 매 프레임 계속 포함되는가"이다. 이탈하는 순간 즉사·스테이지 리셋된다.

이 판정을 어떤 방식으로 구현할지가 미결이었다. 초기 문서 초안에는 "그림자에 닿으면 즉사"라는 터치 판정 서술과 "그리드 기반 우선 검토"라는 미검증 placeholder가 있었으나, 실제 메커니즘을 재확인한 결과 터치가 아닌 **포함(containment) 판정**이 맞는 설계임이 확인됐다. 이에 따라 판정 방식도 다시 검토했다.

제약: 60 FPS 유지가 최우선 비기능 요건이고, 판정이 부정확하면 "억울한 죽음"으로 게임 신뢰도가 무너진다는 리스크가 ARD에 이미 명시돼 있다(`ARD-v1.md` §4). 팀은 2인, 사전과제 마감까지 약 18일이라 구현 난이도도 고려해야 한다.

## 결정

그림자(광원→캐릭터 방향 선분)가 안전 경계 다각형 안에 포함되는지를 **기하학적/벡터 연산**(point-in-polygon + 선분-다각형 교차 판정)으로 확인한다.

**선택: 기하학적/벡터 방식**

## 고려한 대안

| 옵션 | 장점 | 단점 | 탈락 이유 |
|------|------|------|-----------|
| 기하학적/벡터 방식 (채택) | 해석적으로 정확(양자화 오차 없음), readback 없이 O(n) 연산이라 60FPS 여유 큼, 절차 생성이 만드는 다각형 데이터를 그대로 재사용 | 정점·공선 등 경계 케이스를 직접 처리해야 함 | - |
| 그리드(타일) 기반 | 구현이 직관적, 프로토타입 속도가 빠름 | 셀 크기만큼 판정 오차 발생 — 경계 부근에서 "안전한데 죽었다"는 억울한 죽음 리스크를 오히려 키움 | ARD가 명시한 정확성 요건과 정면 충돌 |
| 픽셀 기반 (Canvas getImageData) | 렌더링 결과와 100% 시각적으로 일치 | 매 프레임 Canvas readback이 필요해 저사양 심사 환경에서 60FPS 붕괴 위험, 안티앨리어싱으로 경계 픽셀 판정이 오히려 애매해짐 | 최우선 비기능 요건(60FPS)과 정면 충돌 |

## 결과

**긍정적 결과:**
- 판정 로직이 순수 함수(입력: 그림자 선분, 경계 다각형 / 출력: boolean)로 구현 가능 → 단위 테스트로 정확성 고정
- 절차적 생성이 산출하는 `boundaryPolygon` 데이터를 렌더러·판정기가 그대로 공유 (`Stage` 데이터 계약, `architecture-v1.md` 참조)
- readback 없는 연산이라 저사양 심사 환경에서도 성능 여유 확보

**부정적 결과 / 트레이드오프:**
- 경계를 볼록(convex) 다각형으로 제한하면 판정이 단순해지지만, 오목한 통로 형태의 레벨 디자인이 제약될 수 있음 (필요해지면 simple-polygon 판정으로 전환 가능, 여전히 해석적)
- 그리드 기반보다 초기 구현 시 기하 알고리즘(외적 부호 판정, 선분 교차) 이해가 필요함

**위험 요소:**
- 정점 위/변 위에 정확히 걸치는 공선(collinear) 케이스에서 판정이 애매해질 수 있음 — 완화 방법: 해당 케이스를 단위 테스트로 고정하고 "경계선 위 = 안전"으로 명시적 규칙 확정

## 구현 시 주의사항

- 절차 생성(procgen)은 `boundaryPolygon`을 기본적으로 볼록 다각형으로 생성한다 — 오목 형태가 필요해지기 전까지 판정 로직을 단순하게 유지
- `ShadowCaster`(그림자 선분 계산)와 `ContainmentJudge`(포함 판정)는 분리된 순수 함수로 구현해 각각 독립적으로 테스트한다
- 그림자 길이 `ℓ`의 산출 규칙은 이 ADR의 범위 밖 — P1 플레이테스트로 별도 확정

## 재검토 조건

- 레벨 디자인상 오목한 안전 경계가 반드시 필요해지는 경우 (simple-polygon 판정으로 전환 검토)
- 장애물에 의한 그림자 occlusion을 MVP 이후 범위로 추가하는 경우 (판정 로직에 장애물 교차 검사 추가 필요)
