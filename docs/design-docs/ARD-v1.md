## 1. 품질 속성 목표 (Quality Attributes)

| 속성 | 목표 | 측정 방법 | 우선순위 |
|------|------|-----------|----------|
| 접근성(실행 편의성) | 설치 없이 링크 클릭만으로 브라우저에서 즉시 플레이 | 심사자 관점 실사용 테스트 (링크→플레이 소요 클릭 수) | High |
| 성능 | 저사양 심사 환경에서도 끊김 없는 플레이 (별도 GPU 요구 없음) | 프레임 드랍 육안 체크, 로딩 시간 측정 | High |
| 이식성 | 주요 브라우저(Chrome/Edge) 최신 버전에서 동일 동작 | 크로스 브라우저 수동 테스트 | High |
| 유지보수성 | 48시간 본행사에서 재사용/확장 가능한 단순 구조 | 코드 리뷰, 모듈 분리도 확인 | Medium |
| 규정 준수성 | 대회 제출 규정(웹/앱만, 유료 라이선스 금지 등) 100% 충족 | 제출 전 체크리스트 검증 | High |

## 2. 아키텍처 제약사항

### 기술적 제약
- 웹 브라우저에서 실행 가능해야 함 (PC 실행파일 .exe 제출 불가)
- 별도 유료 라이선스/에셋 스토어 결제 없이 실행 가능해야 함
- GitHub Pages로 정적 배포 가능한 구조 (서버리스 우선 — 별도 백엔드 인프라 최소화)

### 조직적 제약
- 2인 팀 (배영환: 백엔드/아키텍처/데이터, 송원호: 프론트엔드/UI/QA) — API·인터페이스 계약을 초반에 합의하면 병렬 진행 가능한 조합
- 사전과제 마감(2026-08-10)까지 약 19일 — 주제 선정, 구현, 문서화(PDF 3종)까지 포함해야 하므로 아키텍처는 단순함을 최우선

### 예산/인프라 제약
- 예산 사실상 없음 — 무료 티어(GitHub Pages 등) 내에서 해결
- 외부 유료 API/서비스 의존 최소화

## 3. 주요 아키텍처 결정 (초안)

> 상세 결정 기록은 `docs/design-docs/adr/` 에 ADR로 작성합니다. 주제/엔진 확정 전까지는 초안 수준.

| 결정 영역 | 선택 | 근거 |
|-----------|------|------|
| 실행 환경 | 브라우저(클라이언트 사이드) | 설치 없이 심사자가 바로 플레이해야 함 |
| 백엔드 필요 여부 | 기본 불필요 (클라이언트 단독 게임 우선 검토) | 서버 인프라·배포 복잡도 최소화, 무료 정적 호스팅으로 충분 |
| 배포 | GitHub Pages | 대회가 명시적으로 권장하는 방식, 무료, 링크 공유만으로 심사 가능 |
| 게임 엔진/스택 | 미정 (주제 확정 후 결정) | 게임 장르·플레이 방식에 따라 적합한 엔진이 달라짐 |

## 5. 검증 기준

아키텍처가 이 ARD를 만족하는지 확인하는 방법:

- [ ] 링크 클릭만으로 설치 없이 브라우저에서 플레이 가능 (실사용 테스트)
- [ ] Chrome/Edge 최신 버전에서 동일하게 동작
- [ ] 제약사항 위반 없음 — `architecture-guard.sh` 훅 통과
- [ ] 주요 결정사항 ADR 작성 완료 (`docs/design-docs/adr/`)
- [ ] 사전과제 제출 규정 체크리스트 100% 충족
