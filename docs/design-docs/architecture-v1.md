## 1. 시스템 개요

NHN NAN2026 해커톤 사전과제 제출용 웹 게임. 심사자가 GitHub Pages 링크를 클릭해 설치 없이 브라우저에서 바로 플레이할 수 있어야 한다. 게임 주제·장르가 아직 미정이라 아래 구조는 "클라이언트 단독 웹 게임"을 기본 가정으로 한 초안이며, 주제 확정 시 재검토한다.

## 2. 컴포넌트 다이어그램

```
[심사자 / 플레이어 브라우저]
        │
        ▼
[GitHub Pages 정적 호스팅]
        │
        ▼
[게임 클라이언트 (HTML/JS, 엔진 미정)]
    ├──▶ [Game Loop / Scene 관리]
    ├──▶ [Assets (이미지/사운드) — 로컬 번들]
    └──▶ [Local State (localStorage, 필요 시)]

※ 백엔드 서버 없음 — 클라이언트 단독 실행 우선 검토.
  (온라인 랭킹 등 서버 기능이 MVP에 필요해지면 별도 ADR로 재검토)
```

## 3. 레이어 구조

> 엔진 미확정 상태의 제안 구조 — 주제/엔진 확정 후 `docs/design-docs/architecture-layers.md`에 맞춰 갱신.

```
src/
├── scenes/        # 화면 단위 (타이틀, 플레이, 결과 등)
├── entities/       # 게임 오브젝트 (플레이어, 적, 아이템 등)
├── systems/         # 게임 로직 (충돌, 점수, 입력 처리 등)
├── assets/          # 이미지/사운드/폰트
└── core/            # 게임 루프, 설정, 공통 유틸
```

## 4. 데이터 흐름

```
[사용자 입력] → [입력 처리(systems)] → [게임 상태 갱신(entities)] → [렌더링(scenes)] → [화면 출력]
                                                      │
                                                      └─▶ [localStorage] (점수/설정 등, 필요 시)
```

## 5. 주요 설계 결정

| 결정 | 선택 | 이유 | ADR |
|------|------|------|-----|
| 실행 환경 | 브라우저 클라이언트 단독 | 설치 없이 심사자가 즉시 플레이 가능해야 함 | - |
| 배포 | GitHub Pages | 대회 권장 방식, 무료, 링크 공유만으로 심사 가능 | - |
| 백엔드 | 기본 불필요 | 인프라·일정 복잡도 최소화 (ARD 2번 조직적 제약) | - |
| 엔진/스택 | 미정 | 게임 주제·장르 확정 후 결정 | - |

## 6. 비기능 요건 달성 전략

- **접근성**: 정적 파일만으로 구성해 GitHub Pages에 바로 배포, 별도 빌드 서버 불필요
- **성능**: 저사양 환경 고려해 에셋 용량 최소화, 무거운 3D 렌더링 지양(2D 우선 검토)
- **이식성**: Chrome/Edge 기준으로 개발하고 표준 웹 API 위주로 사용, 브라우저별 실험적 기능 지양
- **유지보수성**: `scenes/entities/systems` 분리로 48시간 본행사에서도 구조 재사용 가능하도록 설계

## 7. 보안 고려사항

- 결제/개인정보를 다루지 않는 게임이므로 인증·암호화 요건 없음 (변경 시 재검토)
- 외부 에셋 사용 시 출처·라이선스를 코드 저장소 및 AI활용기술문서에 함께 기록
- 저장소는 공개(public) 제출 권장 — 민감정보(API 키 등)가 커밋되지 않도록 `.gitignore` 유지
