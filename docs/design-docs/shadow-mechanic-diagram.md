## 1. 공간 개념도 — 그림자는 어떻게 결정되는가

광원(태양) 위치 `L`은 스테이지 고정값이다. 캐릭터가 이동하면(`C`) 그림자의 방향과 끝점(`tip`)이 매 프레임 다시 계산된다. **플레이어가 직접 움직이는 것은 캐릭터뿐이고, 그림자는 그 결과로 파생된다.**

```
                              ☀ L (광원, 스테이지 고정)
                             ╱
                            ╱
                           ╱  ← 광원→캐릭터 방향 d = normalize(C - L)
                          ╱
        ┌ ─ ─ ─ ─ ─ ─ ─ ●C ─ ─ ─ ─ ─ ─ ┐   ← 안전 경계(boundary polygon)
        │                │╲              │
        │                │ ╲             │
        │                │  ╲            │
        │                │   ●tip = C + d·ℓ   ← 그림자 끝점 (경계 안 = 생존)
        │                │                │
        └ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘
```

- `C` (캐릭터)와 `tip` (그림자 끝점)을 잇는 선분이 "그림자"다.
- 안전 경계(점선 사각형)는 스테이지마다 절차적으로 생성되는 다각형이다.
- **판정 규칙: 그림자 선분의 두 끝점이 모두 안전 경계 다각형 안에 있어야 한다. 하나라도 벗어나면 그 프레임에 즉사 + 스테이지 리셋.**

---

## 2. 왜 "간접 조작"이 재미인가

캐릭터를 왼쪽으로 옮기면 그림자는 광원 반대 방향으로 더 멀리 뻗어나갈 수도, 오히려 경계 안으로 들어올 수도 있다 — **캐릭터의 이동 방향과 그림자가 안전해지는 방향이 항상 같지는 않다.**

```
[캐릭터를 오른쪽(→)으로 이동시키면]

  광원이 왼쪽 위에 있을 때:            광원이 오른쪽 위에 있을 때:
  그림자 tip은 더 오른쪽 아래로 이동   그림자 tip은 왼쪽 아래로 이동
  (직관과 일치 — 쉬움)                (직관과 반대 — 여기서 실수 유발)
```

이 "직관 vs 실제 필요 이동"의 어긋남이 스테이지 난이도의 핵심 축이며, 절차 생성 AI가 "플레이어가 자주 쓰는 안전한 동선"을 학습해 다음 스테이지에서 그 동선을 막을 때도 바로 이 지점(광원 각도 설계)을 활용한다.

## 3. 프레임 단위 판정 흐름

```mermaid
flowchart LR
    A[키보드 입력] --> B[캐릭터 위치 C 갱신<br/>physics: 벽 충돌 반영]
    B --> C[ShadowCaster<br/>d = normalize(C - L)<br/>tip = C + d·ℓ]
    C --> D{ContainmentJudge<br/>선분(C, tip)이<br/>boundaryPolygon 안?}
    D -- 이탈 --> E[즉사 → 스테이지 리셋]
    D -- 포함 --> F[Canvas 렌더 → 다음 프레임]
    F --> A
```

이 판정은 **매 프레임(60회/초)** 반복된다. 터치(닿음) 판정이 아니라 **포함(containment) 판정**이라는 점이 예전 기획안과의 핵심 차이다.

## 4. 예전 기획(오기획)과 차이

| 항목 | 예전 서술 (폐기됨) | 현재 확정 |
|------|---------------------|-----------|
| 죽음 조건 | 그림자에 "닿으면" 즉사 | 그림자가 안전 경계를 "벗어나면" 즉사 |
| 그림자의 역할 | 피해야 할 장애물 | 플레이어가 간접 조종해야 할 대상 그 자체 |
| 판정 대상 | 그림자 vs 캐릭터/장애물 접촉 | 그림자 vs 스테이지 경계 포함 여부 |
| 판정 방식 | (미확정, 그리드 placeholder) | 기하학적/벡터 방식 (`ADR-001`) |
