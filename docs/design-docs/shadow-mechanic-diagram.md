## 1. 공간 개념도 — 그림자는 어떻게 결정되는가

광원(태양) 위치 `L`은 스테이지 고정값이다. 캐릭터가 이동하면(`C`) 그림자의 방향과 끝점(`tip`)이 매 프레임 다시 계산된다. **플레이어가 직접 움직이는 것은 캐릭터뿐이고, 그림자는 그 결과로 파생된다.**

```
                              ☀ L (광원, 스테이지 고정)
                             ╱
                            ╱
                           ╱  ← 광원→캐릭터 방향 d = normalize(C - L)
                          ╱
        ┌ ─ ─ ─ ─ ─ ─ ─ ●C ─ ─ ─ ─ ─ ─ ┐   ← 안전 경계(boundary polygon)
        │                │╲              │
        │                │ ╲             │
        │                │  ╲            │
        │                │   ●tip = C + d·ℓ   ← 그림자 끝점
        │                │                │
        └ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘
```

- `C` (캐릭터)와 `tip` (그림자 끝점)을 잇는 선분이 "그림자"다.
- 안전 경계(점선 사각형)는 스테이지마다 절차적으로 생성되는 다각형이다.
- **판정 규칙: 그림자 선분의 두 끝점이 모두 안전 경계 다각형 안에 있어야 한다. 하나라도 벗어나면 그 프레임에 즉사 + 스테이지 리셋.**

---

## 2. 왜 "간접 조작"이 재미인가

그림자 끝점은 `tip = C + ℓ·normalize(C - L)`로 계산되므로, 캐릭터 위치 `C`의 이동 자체와 "광원 기준 각도(방향)"의 변화가 함께 반영된다. **캐릭터가 광원에서 멀리 있을 때는 그림자도 대체로 캐릭터와 같은 방향으로 따라 움직이지만, 캐릭터가 광원에 가까워질수록(또는 그림자 길이 ℓ이 광원-캐릭터 거리보다 커질수록) 작은 이동에도 광원 기준 각도가 크게 회전해, 그림자가 캐릭터 이동 방향과 다르게(때로는 반대로) 튈 수 있다.** (가로등 바로 아래를 지날 때 그림자가 휙 돌아가는 것과 같은 원리.)

```
[광원에서 먼 경우 — 직관과 대체로 일치]        [광원에 가까운 경우 — 각도가 급격히 회전]
캐릭터가 조금 이동                            캐릭터가 조금 이동
→ 그림자도 대체로 같은 방향으로 따라옴          → 광원 기준 각도가 크게 바뀌어
                                              그림자 끝점이 예상과 다른 방향으로 튐
```

이 "광원 근접 지점에서 그림자가 급격히 꺾이는" 구간이 스테이지 난이도의 핵심 축이 될 수 있다 — 절차 생성 시 이런 구간을 의도적으로 배치하면 까다로운 퍼즐을 만들 수 있고, 초반 스테이지는 광원에서 먼 완만한 구간 위주로 구성해 학습 곡선을 완만하게 할 수 있다.

> 불확실함: 정확히 어느 지점부터 "반전"이 체감될 정도로 일어나는지는 그림자 길이 `ℓ` 값이 P1에서 확정된 후 실제로 플레이해보며 측정해야 한다.

## 3. 프레임 단위 판정 흐름

```mermaid
flowchart LR
    A[키보드 입력] --> B[캐릭터 위치 C 갱신<br/>physics: 벽 충돌 반영]
    B --> C[ShadowCaster<br/>d = normalize(C - L)<br/>tip = C + d·ℓ]
    C --> D{ContainmentJudge<br/>선분(C, tip)이<br/>boundaryPolygon 안?}
    D -- 이탈 --> E[즉사 → 스테이지 리셋]
    D -- 포함 --> F[Canvas 렌더 → 다음 프레임]
    F --> A
```

이 판정은 **매 프레임(60회/초)** 반복된다. 터치(닿음) 판정이 아니라 **포함(containment) 판정**이라는 점이 예전 기획안과의 핵심 차이다.
